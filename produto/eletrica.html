Como ler

Três coisas diferentes

Desenho, placa de referência e máquina montada não são a mesma prova.

O repositório YB-projeto-eletrico-publico é o projeto elétrico em KiCad. O dono do produto trata esse projeto como provavelmente igual ao que está montado em campo. Isso continua A confirmar até alguém comparar o desenho com a máquina.

A placa que o firmware descreve como alvo está no README da branch campo-1.0.3: ESP32-S3-WROOM-1 numa base JNG-E / ENELTEC JOKER. O repositório YB-modulo-basico-pcb-principal-joker-publico chama a PCB Core V1.1, de codinome Joker, de referência de produção. Qual revisão está na máquina de campo está A confirmar.

O ambiente de compilação usa o nome de placa esp32-s3-devkitc-1. Esse nome é o alvo do PlatformIO. Não é, por si só, a prova de que a máquina de campo usa um DevKit solto.

Projeto elétrico: README de YB-projeto-eletrico-publico e carimbo de projeto-eletrico.kicad_sch. Placa: README do firmware, seção Hardware Alvo, e README do repositório Joker. Compilação: platformio.ini, linhas 11 a 13.

Deslize o diagrama para o lado.

O display SH1107, endereço 0x3C, também fica no barramento Wire. O diagrama não inclui modelo comercial de sensor, fonte ou bateria. Os modelos confirmados estão em Alimentação e em Sensores.

Barramentos

No boot, o firmware abre dois I²C. Wire.begin usa os pinos SDA 8 e SCL 9. Wire1.begin usa SDA 11 e SCL 13. Os dois relógios ficam em 100 kHz. O MCP23017 mora só no segundo barramento, no endereço 0x20. Um PCF8574 usa o mesmo número 0x20, mas no primeiro barramento. São chips diferentes em fios diferentes.

estado_boot.cpp, linhas 49 e 53. defines.h, linhas 14, 15, 16, 17 e 23. dispositivos_mcp.cpp, begin_I2C com Wire1. dispositivos_pcf.h, linhas 10 e 11. dispositivos_mcp.h, linha 10.

Controlador
ESP32-S3. O README do firmware cita o módulo ESP32-S3-WROOM-1, dois núcleos, e a base JNG-E / ENELTEC JOKER.README, seções Hardware Alvo e Hardware e Mapeamento. Núcleos no src/main.cpp.
Flash na compilação
16 MB, sistema de arquivos LittleFS, tabela custom_partitions.csv.platformio.ini, linhas 47 a 49.
Partições no CSV
app0 e app1 com 0x300000 cada uma. A partição de dados se chama spiffs e tem 0x9D0000. O README resume isso como 4 MB de aplicação, 9,9 MB de arquivos e 2 MB de OTA. O número que vale para o build é o do CSV.custom_partitions.csv, linhas 3, 4 e 6. Divergência com o README.
PSRAM
O platformio.ini liga a PSRAM. O README fala em 8 MB de PSRAM e 512 KB de SRAM. O tamanho montado na placa de campo está a confirmar.platformio.ini, linha 55. README, Hardware Alvo.
Display
SH1107, 128 por 128, endereço 0x3C.lib/display/src/display.h, linhas 49, 50 e 52.
Modem
O código seleciona o SIM7080 e usa Serial0, com baud padrão 115200. O README ainda aponta TX no GPIO 43 e RX no GPIO 44.defines.h, linhas 27, 28 e 31.
3 V dos módulos
No boot o GPIO 47 vai para nível alto, com o comentário de habilitar a alimentação de 3,3 V dos módulos externos.defines.h, linha 21. estado_boot.cpp, linhas 44 e 45.
RTC
O README lista um DS1307 no endereço 0x68, no Wire, como reserva quando o NTP não está disponível. Se esse chip está soldado na máquina de campo está a confirmar.

Energia

O que o desenho nomeia

Na folha de alimentação aparecem os rótulos Fonte-Chaveada, Painel Solar 1, Painel Solar 2, Placa Seletora, Placa Core e Bateria - 3S. São nomes do desenho. A fonte é a do projeto IFF: uma fonte chaveada de 12 V / 20 A, ligada na entrada P1 da chave seletora. O modelo exato não ficou registrado. A bateria é um pack de 18650, 3S3P, 11,1 V / 6,48 Ah. Resolvido: confirmado pelo Rodrigo em 14/10/2026 às 17h38.

O documento de campo já publicado diz que a rede no local é de 220 V, informado pelo dono do produto. O README da placa seletora descreve uma entrada A de 110/220 V para 12 V em corrente contínua, além de 12 V direto, gerador, MPPT solar e geração manual. Se a seletora, os painéis e a bateria do desenho são os que estão instalados está A confirmar.

Alimentacao.kicad_sch, propriedades Value desses símbolos. Rede de 220 V: index.html deste repositório, seção Hidráulica, fonte "Informado pelo dono do produto". Seletora: README de YB-modulo-basico-pcb-seletor-de-alimentacao-publico. Fonte e bateria: confirmado pelo Rodrigo em 14/10/2026; bateria em 04_eletrico.md e 07_montagem_fisica.md, no Drive da Wara.

Faixas de tensão no arquivo do repositório

Os dois JSON do firmware trazem os mesmos números de tensão: alimentação normal 12,4, baixo 10,0 e muito baixo 8,0; bateria normal 12,3, baixo 10,5 e muito baixo 10,0. A comparação que desligaria a bomba por tensão baixa está comentada no código e substituída por um valor fixo verdadeiro. Essas faixas são do arquivo do repositório. O que está gravado na placa de campo está a confirmar.

data/config.json, linhas 81 a 90. data/config-padrao-fabrica.json, linhas 79 a 88. estado_controlar_tratamento.cpp, linha 121, onde bomba_eletrica_tensao_normal recebe true.

Campo

Sensores no desenho

A folha de sensores desenha um Sensor de Fluxo, dois sensores de nível, Transdutor 1, Transdutor 2 e a Placa Core. Textos no desenho citam PT100, PT101, PT102 e PT103. Não há um texto PT104 nessa folha. O firmware lê cinco canais de pressão, do PT100 ao PT104, e o David confirmou em 14/10/2026 que são 5 sensores de pressão (ver Hidráulica). O quinto canal não aparece nessa folha do desenho de campo.

Nenhum desses símbolos traz fabricante ou código de catálogo. O sensor de pressão é o HK2404, rosca G1/4, 0,5 MPa, 5 V. Foram compradas 5 unidades em 30/07/2026 (tarefa 86e2jrwc5 no ClickUp). Resolvido: confirmado pelo Rodrigo em 14/10/2026 às 17h38. O modelo do sensor de vazão está A confirmar. O desenho também escreve LSL200, LSLL200 e VALVULA 1 a 4. Esses textos não são os índices 0 a 15 do MCP23017. A função hidráulica de cada índice, quando aparece na página de firmware, vem do documento de campo informado pelo dono do produto, não deste esquemático.

Sensores.kicad_sch: valores dos símbolos e textos PT100 a PT103, LSL200, LSLL200 e VALVULA. Canais do firmware: lib/dispositivos_ads/src/dispositivos_ads.cpp, linhas 12 a 20.
